# デバッガリファレンス

エミュレータには、実行中のどの時点でも開けるインタラクティブなデバッグ REPL があります。Z80 と VDP の状態の確認、ブレークポイントとウォッチポイントの設定、ステップ実行、トレースができます。

**⚙V9938** の印は、MSX2 / V9938 のマシンでだけ使えるコマンドや出力形式を示します。MSX1 / TMS9918A では、`rp` は例外を送出せずにエラーメッセージを表示し、`v` と `rv` は TMS9918A 用の形式で表示します。

ソース：`host/debugger/prompt.py`（REPL）、`msx/vdp/v9938.py` / `msx/vdp/v9938_renderer.py`（VDP）、`host/trace.py`（VDP とマッパーのトレースの文字列）

---

## デバッガへの入り方

### Ctrl+C

エミュレータを実行しているターミナル（または SDL ウィンドウ）で **Ctrl+C** を押します。ターミナルでは、フレーム内の次の区間に入る前にエミュレーションが止まります。止まるまでの遅れは長くても約 1 フレームです。SDL ウィンドウでは、フレームとフレームの間で止まります。デバッガは現在の PC を逆アセンブルし、REPL のプロンプトを表示します。

```
Debugger entered. Type 'c' to resume, 'q' to exit.
  PC=C010h  3E 01        LD A,01h
(msx-dbg cyc=720430 frm=12)
```

`cyc` は Z80 の T ステート数の累計、`frm` は終わったフレームの数です。ウィンドウには最後に描画したフレームが表示されます。SDL ウィンドウで Ctrl+C を押した場合も、REPL のコマンドはエミュレータを起動したターミナルで入力します。`c` を入力するまで、ウィンドウの表示は更新されません。

`c` でエミュレーションを再開し、`q` でエミュレータを終了します。ブレークや Ctrl+C で止まったフレームは、止まった位置から続くので、そのフレームの VBlank と残りのスキャンラインも実行されます。REPL のプロンプトでもう一度 Ctrl+C を押すと、エミュレータはすぐに終了します（`sys.exit(0)`）。入力の取り消しやプロンプトへの復帰にはなりません。

`--rpc` を付けて起動した場合も、ターミナルで Ctrl+C を押すと REPL が開きます。RPC の一時停止状態は変わりません。REPL が開いている間、エミュレータは RPC の要求を処理しないので、`c` を入力するまで RPC の呼び出しはタイムアウトします。ブレークポイントやウォッチポイントにヒットしたときは、REPL は開かず、RPC サーバが一時停止します。

### 行編集と履歴

`readline` モジュールは、macOS と Linux では標準の CPython にも PyPy にも入っています。使える環境では、プロンプトで通常の行編集と、全コマンド名の Tab 補完ができます。コマンドの履歴も、実行をまたいで最新の 500 件まで残ります。履歴のファイルは、CPython では `~/.msx_dbg_history_cpython`、PyPy では `~/.msx_dbg_history_pypy` です。2 つのインタプリタは履歴を違う書式で書くので、ファイルを分けています。デバッガは REPL を開くときに履歴を読み込み、エミュレーションを再開するときに書き出します。Windows の標準の CPython には `readline` がありません。そこでも REPL は動きますが、行編集、補完、履歴は使えません。

### 起動時にブレークポイントとウォッチポイントを設定する

SDL ウィンドウが開く前にブレークポイントやウォッチポイントを設定するには、CLI のフラグを使います。どちらのフラグも、MSX1 と MSX2 のどのマシンでも使えます。

```bash
# 実行ブレークポイント — 最大 4 個、カンマ区切りの 16 進アドレス（0x プレフィックスなし）
python . path/to/game.rom --machine cbios_msx2_jp --break-point C000,D000

# ウォッチポイント — addr[,r|w|rw] ペアをカンマ区切りで指定。デフォルトのモードは rw
python . path/to/game.rom --machine cbios_msx1_jp --watch-point ca4a,w,fedc,rw
```

起動時に、エミュレータは設定中のブレークポイントとウォッチポイントを、`break   : C000h, D000h` と `watch   : CA4Ah[w], FEDCh[rw]` の形式の行で stdout に書き出します。

## コマンドリファレンス

**`h`**、**`?`**：コマンドの一覧を 1 行にまとめて表示します。不明なコマンドを入力したときも、この一覧を自動で表示します。

デバッガはコマンドの引数を空白で分けます。スペースを含むパスはダブルクォートで囲み、`fdd1 "MY DISK 1.dsk"` や `ld "saves/states/my checkpoint.state"` のように書きます。この書き方は、ファイル名を取るすべてのコマンド（`fdd1`/`fdd2`、`ld`、`sv`、`dvf`）に当てはまります。閉じていないクォートがあると、デバッガは `Parse error` を表示し、エミュレータの状態は変えません。

### 実行制御

**`c`**：エミュレーションを再開します。

**`q`**：エミュレータを終了します。プロセスの終了コードは 0 です。

**`reset`**：CPU、PSG、VDP、PPI、プライマリ/セカンダリスロットレジスタ、すべてのカートリッジマッパーを、電源投入時の状態に完全にリセットします。SCC、FM-PAC、FDC、漢字 ROM、プリンタポート、RAM マッパーも、マシンにあればリセットします。メモリと VRAM の内容はそのまま残ります。リセットの後は、`c` と同じくそのままエミュレーションを再開します。リセット前の PC には調べるものが残っていないためです。

**`s [N]`**：Z80 の命令を `N` 個ステップ実行します（10 進、デフォルトは 1）。ステップの後に、簡潔なレジスタの要約と次の命令を表示します。

```
  PC=C012  AF=0100  BC=0010  DE=0000  HL=C100
  => C012: CD 40 C0     CALL C040h
```

1 ステップでは、止まっているフレームの中で 1 命令を実行するので、プロンプトの `cyc` はその命令の T ステート数だけ増え、ステップがスキャンライン、VBlank、フレームの終わりをまたぐこともあります。ステップはブレークポイントでは止まりません。

**`g ADDR`**：エミュレーションを再開し、PC が `ADDR`（16 進）に達するまで実行します。`g` が置くのは一度だけ有効な一時ブレークポイントで、ヒットするとデバッガが消します。`ba` の 4 個の上限には数えず、常設のブレークポイントも変えません。

**`gf N`**：エミュレーションを再開し、フレームカウンタ（プロンプトの `frm=` の値）が 10 進の `N` に達するまで実行します。この判定は一度だけ有効です。コアはこの条件を、命令ごとではなく各フレームの終わりに 1 回だけ調べます（描画しなかったフレームでも調べます）。そのため、設定中の `ba`/`g` のブレークポイントと違って、実行は遅くなりません。`N` には現在のフレーム数より大きい値を指定します。そうでないときは、`gf` はエラーを表示して再開しません。

**`so`**：ステップアウトします。`so` を入力した時点の SP の値より、SP が大きくなるまで（つまり現在のルーチンが戻るまで）実行します。例外的なケースは「既知の制限」で説明します。

### ブレークポイント

**`ba ADDR`**：`ADDR`（16 進、`0x` プレフィックスなし）に実行ブレークポイントを追加します。最大 4 個まで置けます。PC が一致すると、エミュレーションが一時停止して REPL が開きます。

**`br ADDR`**：`ADDR` のブレークポイントを消します。そのアドレスにブレークポイントが設定されていないときは、エラーを表示します。

**`bl`**：設定中のブレークポイントを一覧表示します。

#### クラッシュの兆候で自動的に止める

**`bh`**：割り込み禁止中の HALT で止めるかどうかを切り替えます。CPU が `iff1 == 0` の状態で `HALT` を実行した瞬間に止まります。この HALT から復帰させる割り込みはもう来ないので、完全なハングを示す兆候です。条件が偽から真に変わった時点で 1 回だけ止まります。条件が成り立ったまま再開しても、再び止まることはありません。

**`bs [LOW HIGH | off]`**：SP が有効な RAM の範囲を外れたときに止まります。

- `bs`（引数なし）：マシンの RAM の構成から計算した範囲で有効にします。スロット 3 にある MSX1 のフラットな RAM では、メモリの上端の範囲です。スロット 0 にある RAM（`hb_10` など）では、その RAM のあるページの範囲です。MSX2 のマッパー RAM では、アドレス空間の全体の範囲です。
- `bs LOW HIGH`：両端を含む 16 進の範囲を指定して有効にします。LOW が HIGH より大きいときは、デバッガが入れ替えます。
- `bs off`：無効にします。

SP を有効な範囲の外に動かした最初の命令で止まるので、スタックの破壊を見つけられます。止まるのは、条件が偽から真に変わった時点だけです。

### ウォッチポイント

**`wa ADDR[,r|w|rw]`**：`ADDR` にウォッチポイントを追加します。モードは `r`（読み出しで止まる）、`w`（書き込みで止まる）、`rw`（両方、デフォルト）です。最大 4 個まで置けます。モードは空白で区切って書くこともできます（`wa CA4A w`）。すでにウォッチポイントがあるアドレスに `wa` を使うと、そのモードを変えます。

ヒットすると、次の行を表示します。

```
[WP] READ  CA4Ah = 02h  PC=C024h
```

または

```
[WP] WRITE CA4Ah = 05h  PC=C030h
```

その後で REPL が開きます。エミュレーションは、アクセスした命令が終わってから止まります。そのため、ウォッチ対象への書き込みは、REPL が開いた時点ですでにメモリに入っています。`PC=` はその命令のアドレスで、REPL は次の命令を表示します。

`s` で実行した命令がウォッチポイントにヒットしたときは、ステップの要約の前に同じ行を表示します。REPL はそのままプロンプトにとどまります。

**`wd ADDR`**：`ADDR` のウォッチポイントを消します。

**`wl`**：設定中のウォッチポイントを、モードと一緒に一覧表示します。

### CPU の状態

**`rc`**：Z80 のすべてのレジスタをダンプします。

```
AF=5A00  BC=0010  DE=0000  HL=C100  IX=F380  IY=FC40  SP=F3E0  PC=C010
  S=0  Z=1  H=0  P/V=0  N=0  C=0
```

**`da [ADDR]`**：`ADDR`（16 進）から 10 命令を逆アセンブルします。`ADDR` を省くと、現在の PC から始めます。

```
  C010: 3E 01        LD A,01h
  C012: CD 40 C0     CALL C040h
  C015: 21 00 C1     LD HL,C100h
  ...
```

---

### メモリダンプ

**`dm ADDR [SIZE]`**：CPU のアドレス空間を 16 進と ASCII でダンプします。引数はどちらも 16 進で、SIZE のデフォルトは 0x80（128 バイト）です。

```
  F000: 00 01 02 03 04 05 06 07 08 09 0A 0B 0C 0D 0E 0F  ................
  F010: 41 42 43 44 45 46 47 48 49 4A 4B 4C 4D 4E 4F 50  ABCDEFGHIJKLMNOP
```

**`dv VADDR [SIZE]`**：VRAM を 16 進と ASCII でダンプします。引数はどちらも 16 進で、SIZE のデフォルトは 0x80 です。アドレスは VRAM のサイズの中で折り返します（TMS9918A は 0x3FFF、V9938 は 0x1FFFF）。アドレスの表示幅は自動で調整します。

**`dvf FILE`**：VRAM の全内容を、生のバイナリファイルに書き出します。オフラインでの比較や、参照用のツールへの読み込みに使います。

---

### VDP の状態

**`v`**：VDP の状態の要約を表示します。

V9938 の場合（⚙V9938）：

```
  Screen : SCREEN5 (GRAPHIC4)
  VRAM   : Name=00000  Color=02000  Pattern=00800  SprAttr=07600  SprPat=07800
  Disp   : EN=ON   SPR=ON   192L  NTSC     Spr= 8x8 /mag=x1  FG=F BG=1  IE0
  CMD    : LMMC  IMP/T  [IDLE]  SRC=(0,0)  DST=(208,97)  SIZE=(8,8)  CLR=00  DIR=→↓
  Status : S#0=04 (  5S=0 C=0)  S#2=82 (TR   )
```

TMS9918A の場合：

```
  Screen : SCREEN2 (GRAPHIC2)
  VRAM   : Name=1800  Color=27C0  Pat=0000  SprAttr=1B00  SprPat=3800
  Disp   : EN=1  h=192  FG=F  BG=5  size=8  mag=0
  Status : S#0=04
```

**`rv`**：VDP のレジスタをダンプします。

V9938 の場合（⚙V9938）：R#0〜R#27（表示レジスタ）と R#32〜R#46（コマンドレジスタ）を、1 行に 8 個ずつ表示します。

```
  R#0=00  R#1=72  R#2=1F  R#3=FF  R#4=3F  R#5=7F  R#6=07  R#7=00
  R#8=08  R#9=80  R#10=00  R#11=00  R#12=00  R#13=00  R#14=00  R#15=00
  ...
  R#32=00  R#33=00  R#34=00  R#35=00  R#36=00  R#37=00  R#38=00  R#39=00
  ...
```

TMS9918A の場合：R#0〜R#7 を 1 行で表示します。

**`rp`** ⚙V9938：パレットをダンプします。16 個のエントリすべてを `#N=XXX(R,G,B)` の形で表示します。XXX は 9 ビットの値（bit 8〜6 が R、bit 5〜3 が G、bit 2〜0 が B）、R/G/B は各チャンネルの 3 ビットの値です。

```
  #0=000(0,0,0)  #1=000(0,0,0)  #2=071(1,6,1)  #3=1FB(3,7,3)  ...
  #8=1C9(7,1,1)  #9=1DB(7,3,3)  #A=1B1(6,6,1)  #B=1B4(6,6,4)  ...
```

TMS9918A にはプログラマブルなパレットがないので、`rp` はエラーを表示します。

### スプライト

**`ds`**：スプライトの描画のオン/オフを切り替えます。どちらの VDP でも使えます。オフにすると、レンダラは背景のレイヤーだけを描きます。スプライトが原因の表示の乱れを切り分けるときに使います。設定は、もう一度切り替えるかエミュレータを終了するまで続きます。

---

### トレース

**`te`**：VDP レジスタ書き込みのトレースを有効にします。どちらの VDP でも使えます。エミュレーション中、レジスタへの書き込みごとに 1 行を stdout に書き出します。起動時に `--vdp-trace-out FILE` を指定した場合は、そのファイルに書き出します。

```
CY=0000012450 FR=000003 PC=C018 VDP_REG R#02=1Fh
CY=0000012460 FR=000003 PC=C01C VDP_REG R#05=7Fh
```

書き込みはコアが記録し、デバッガは各フレームの終わりと `s` の各ステップの後に行を書き出します。そのため、1 フレーム分の行は、そのフレームを実行した後にまとめて書き出されます。

VDP コマンドを開始する R#46 への書き込みは、`VDP_REG` 行ではなく `VDP_CMD` 行になります。この行には、コマンド、論理演算、R#46 に書き込んだ値が出ます。さらに、前回の R#46 への書き込み以降に R#32〜R#45 へ書き込まれた値も出ます（書き込みのないレジスタは `--`）。

```
CY=0000013000 FR=000003 PC=C030 VDP_CMD HMMV/IMP  (C0h) R32-45=['--','--','--','--','00','00','00','00','00','01','D4','00','00','00']
```

ポート 0x9B（間接レジスタアクセス）経由でレジスタに書き込んだときは、行の末尾に `;port 9Bh` が付きます。

**`td`**：VDP レジスタのトレースを無効にします。すでに無効のときは、メッセージを表示します。

**`ce`**：カートリッジマッパーのバンク切り替えトレースを有効にします。バンクレジスタへの書き込みでウィンドウのバンクが変わるたびに、1 行を書き出します。

```
CY=0000025000 FR=000005 PC=5B2A MAP_BANK win=1 03h->05h addr=6001h
```

`win` はマッパーのウィンドウの番号、`addr` はレジスタに書き込んだアドレスです。デバッガは、VDP のトレースと同じく、各フレームの終わりと `s` の各ステップの後に、行を stdout か `--mapper-trace-out` のファイルに書き出します。スロット 1 にも 2 にもバンク切り替えのあるマッパーがないときは、`ce` はメッセージを表示します。

**`cd`**：マッパーのバンク切り替えトレースを無効にします。

### スロットインスペクタ

**`sl`**：現在のスロットの割り当てを表で表示します。ページ（P0〜P3）ごとに 1 行で、アドレスの範囲、プライマリスロット、セカンダリスロット、中身、バンク/セグメントを示します。

```
  Page  Addr        Prim  Sec  Content                          Bank
  P0    0000-3FFF   0     -    ROM cbios_main_msx2_jp.rom       -
  P1    4000-7FFF   1     -    Cartridge Ascii8                 w0=b2@04000  w1=b0@00000
  P2    8000-BFFF   1     -    Cartridge Ascii8                 w2=b3@06000  w3=b1@02000
  P3    C000-FFFF   3     2    RAM (mapper:standard)            seg=2
```

Bank 列の値は次のとおりです。

- RAM マッパーのページ：`seg=N`
- カートリッジマッパーのページ：そのページの各ウィンドウに割り当てたもの、つまりそのウィンドウから読み出したときに見える内容を表示します。16 KB のウィンドウは `bank N @XXXXX-YYYYY`（ASCII16、R-Type、FM-PAC）、8 KB のウィンドウは `wW=bN@XXXXX`（ASCII8、Konami、SCC、Game Master 2、Halnote）になります。N はウィンドウが実際に割り当てているページです。ゲストが書いた値が ROM の範囲を超えるときは、N はその値と違うことがあります。
- SRAM を割り当てたウィンドウ：バンクの代わりに、SRAM の中のオフセット `SRAM@XXXX` を表示します（`bank SRAM@0000`、`w3=SRAM@1000`）。Halnote では、ページ 0 の SRAM を `SRAM@0000-3FFF` と表示します。Halnote のサブマッパーは、ページ 1 に `sub=…` を足します。
- ROM の終わりより先のウィンドウ（読むと 0xFF）：`open`
- フラットな ROM、BIOS、通常の RAM：`-`

`sl` は、スロット 0 の各ページについて、読み出したときに返る内容を表示します。`hb_10` では、ページ 3 の RAM は `RAM` と表示します。ページ 2 はメイン ROM の終わりより先にあり、読むと 0xFF を返すので、`empty` と表示します。

**`st`**：スロットツリーを表示します。プライマリスロット 0〜3 を順に見て、拡張スロットはサブスロットの構造をすべて表示します。

```
  Primary 0  ROM cbios_main_msx2_jp.rom  32KB
  Primary 1  [cartridge slot]  Cartridge Ascii8
  Primary 2  [cartridge slot]  Cartridge (empty)
  Primary 3 [EXPANDED]  secondary-select(raw)=A0h
    page-map: P0->3-0  P1->3-0  P2->3-2  P3->3-2
    3-0  ROM cbios_sub.rom  16KB
    3-1  empty
    3-2  RAM (mapper:standard)  128KB
    3-3  empty
```

MSX1 のマシンには拡張スロットがないので、`st` はスロット 3 を拡張されていないプライマリスロットとして表示します。

拡張されていないスロットで、あるページの中身がスロット本来の中身と違うときは、`st` はそのページの行をスロットの行の下に足します。たとえば `hb_10` のスロット 0 は、ページ 0〜1 がメイン ROM、ページ 3 が 16 KB の RAM なので、次のように表示します。

```
  Primary 0  ROM hb-10_basic-bios1.rom  32KB
    P3  RAM  16KB
```

### フロッピーディスク

**`fdd1 [FILE|-]`**、**`fdd2 [FILE|-]`**：ドライブ A / B のディスクの確認、交換、取り出しをします。フロッピーインターフェースを持つマシン（例：`hb_f1xd`、`fs_a1f`）で使えます。

- 引数なしでは、現在マウントしているもの（パスか `empty`）を表示します。
- パスを指定すると、その `*.dsk` ファイルをマウントします。パスにはカレントディレクトリからの相対パスと絶対パスのどちらも使え、`~` も展開します。次の `c`（再開）で、コントローラはディスクチェンジ信号で新しいディスクを認識します。交換の処理は両方の接続方式で共通なので、WD2793 のマシンでも TC8566AF のマシンでも同じ動作になります。
- `-` で、現在のディスクを取り出します。

失敗したとき（ファイルがない、イメージを読めない、そのドライブがない）は、エラーを表示し、現在のディスクは変えません。フロッピーインターフェースのないマシンでは `this machine has no floppy interface` と表示します。

```
(msx-dbg cyc=720000 frm=12) fdd1
fdd1: /path/to/game.dsk
(msx-dbg cyc=720000 frm=12) fdd1 disk2.dsk
fdd1: mounted disk2.dsk
(msx-dbg cyc=720000 frm=12) fdd1 "MY DISK 1.dsk"
fdd1: mounted MY DISK 1.dsk
(msx-dbg cyc=720000 frm=12) fdd1 -
fdd1: ejected
```

### カセットテープ

**`tape [blocks|load FILE|eject|rewind|seek SECONDS|seek #N]`**：カセットテープの状態を確認、変更します。カセットポートを持つマシン（例：`hb_10`、`hb_f1xd`）で使えます。

- 引数なしでは、ファイル、秒で表した位置とその位置のブロック、テープの長さ、モーターの状態（テープがなければ `empty`）を表示します。
- `blocks` はファイルのブロックを一覧にします。番号、タイプ（ファイルヘッダは `binary`、`basic`、`ascii`、ほかのブロックは `data`）、ファイル名、秒で表した開始位置、バイト数を表示します。
- `load FILE` は `.cas` ファイルを変換して位置 0 でマウントし、変換の警告を表示します。対応するのは CAS だけです。WAV ファイルは受け付けず、外部ツールで変換するよう促すメッセージを表示します。この変換には [`tools/wav2cas.py`](../tools/README_tools_ja.md#wav2caspy) を使えます。
- `eject` はテープを取り出し、`rewind` は位置を 0 に戻します。
- `seek SECONDS` は位置を秒で指定し、`seek #N` はブロック N の先頭に移ります。

モーターを動かすコマンドはありません。モーターを回したり止めたりするのはゲストだけです（例：`CLOAD`、`BLOAD"CAS:"`）。失敗したとき（ファイルがないか不正、位置がテープの範囲外、テープがない、カセットポートがない）は、エラーを表示し、テープは変えません。カセットポートのないマシンでは、`tape load` は `this machine has no cassette port` と表示します。

```
(msx-dbg cyc=720000 frm=12) tape load game.cas
tape: mounted game.cas (2 blocks)
(msx-dbg cyc=720000 frm=12) tape
tape: game.cas  0.00 s (block 0) / 48.15 s  motor off
(msx-dbg cyc=720000 frm=12) tape blocks
  #0   binary  GAME        0.00 s  16 bytes
  #1   data                8.81 s  4000 bytes
(msx-dbg cyc=720000 frm=12) tape seek #1
tape: game.cas  8.81 s (block 1) / 48.15 s  motor off
(msx-dbg cyc=720000 frm=12) tape seek 99
tape: tape position 354374955 is outside 0-172343159
```

### スクリーンショット

**`ss`**：現在の VDP の状態を描画し、`saves/screenshots/screenshot_YYYYMMDD_HHMMSS.png` に保存します。F10 のホットキーと同じ保存先です。

```
(msx-dbg cyc=724321 frm=12) ss
screenshot saved: saves/screenshots/screenshot_20260101_120000.png
```

`ss` は内部のフレームカウンタを変えず、エミュレーションの状態にも影響しません。同じ停止の時点で取った `v`/`dv`/`rv` の出力と、画面の様子を見比べるときに使います。

### ステートセーブ/ロード

**`sv [TITLE]`**：マシンの全状態を `saves/states/<title>_YYYYMMDD_HHMMSS.state` に保存します。ソケット RPC の `state.save` メソッドと同じ形式、同じ保存先です（[`docs/socket-rpc-mcp_ja.md`](socket-rpc-mcp_ja.md) を参照）。引数はタイトルで、ファイルのパスではありません。引数がなければデフォルトのタイトルを使います。REPL は開いたままになります。

`sv` は同じ名前の PNG のサムネイルも書き出し、`saves/states/latest.state` と `latest.png` が新しいファイルを指すように更新します。保存の前に、マウントしているディスクへの変更を `.dsk` ファイルに書き戻すので、ステートとディスクのファイルは一致します。

**`ld FILE`**：以前に保存した `.state` ファイルから、ステートを復元します。REPL は開いたままで、自動では再開しません。そのため、読み込んだステートを調べたり、`s` や `gf` で正確に進めたりできます。次の場合、`ld` はエラーを表示します。例外は送出せず、状態も変えません。

- ファイルがありません。
- スナップショットの `format_version` に互換性がありません。
- スナップショットが、違うマシン構成（マシン、拡張、カートリッジ ROM）のものです。
- ドライブに、保存したときと同じディスクが入っていません。`ld` はディスクを入れ替えないので、先に `fdd1`/`fdd2` で入れ替えます。
- デッキに、保存したときと同じテープが入っていません。`ld` はテープを変えないので、先に `tape load` でマウントします。

```
(msx-dbg cyc=720000 frm=1999) sv before-glitch
state saved: saves/states/before-glitch_20260101_120000.state
(msx-dbg cyc=720000 frm=1999) gf 2080
  Running to frame 2080 ...

... （フレーム 2080 に到達すると再度 REPL が開く） ...
(msx-dbg cyc=... frm=2080) ld saves/states/before-glitch_20260101_120000.state
state loaded: saves/states/before-glitch_20260101_120000.state
  Loaded state from saves/states/before-glitch_20260101_120000.state
(msx-dbg cyc=720000 frm=1999) gf 2001
  Running to frame 2001 ...
```

## 起動時のトレース（ヘッドレスでの記録）

次のオプションは、最初のフレームの前からトレースを始めます。REPL を開かなくても使えます。

### VDP レジスタのトレース

```bash
# VDP_REG 行を stdout に出力
python . path/to/game.rom --machine cbios_msx2_jp --vdp-trace

# ファイルにリダイレクト
python . path/to/game.rom --machine cbios_msx2_jp --vdp-trace --vdp-trace-out trace.log
```

出力の形式：`CY=.. FR=.. PC=.. VDP_REG R#NN=XXh`。R#46 への書き込みは `VDP_CMD` 行になります（`te` を参照）。

`--vdp-trace` はどちらの VDP もトレースします。MSX1 のマシンの TMS9918A も対象です。

### マッパーのバンク切り替えトレース

```bash
python . path/to/game.rom --machine cbios_msx2_jp --mapper-trace
python . path/to/game.rom --machine cbios_msx2_jp --mapper-trace --mapper-trace-out banks.log
```

出力の形式：`CY=.. FR=.. PC=.. MAP_BANK win=W OLDh->NEWh addr=XXXXh`

カートリッジマッパーがフラット（バンク切り替えなし）のときは、エミュレータは stderr に注記を書き出し、`MAP_BANK` の行は書き出しません。

### 診断ログ

```bash
python . path/to/game.rom --machine cbios_msx2_jp --debug
python . path/to/game.rom --machine cbios_msx2_jp --debug --log debug.log
```

`--debug` を付けると、診断ログを stderr に書き出します。`--log FILE` を付けると、同じログを `FILE` にも追記します。`--log` には `--debug` が必要です。`--debug` がないと、`--log` は無視され、ファイルも作られません。各行の先頭には、次のカテゴリが付きます。

| カテゴリ | 内容                                                                                                                       |
| -------- | -------------------------------------------------------------------------------------------------------------------------- |
| `[IO]`   | I/O ポートへのアクセスごとの `IN` または `OUT`（ポート、値、命令の PC 付き）。カセットのモーターの変化（テープの位置付き） |
| `[BOOT]` | VDP の画面表示のオンとオフ（R#1）、またはスクリーンモードの変化（R#0、R#1）                                                |
| `[CPU]`  | 未定義の命令、またはハング直前の命令履歴（1 行に 1 命令）                                                                  |
| `[HANG]` | 同じ PC を 1000 回続けて実行したとき、またはフレームの終わりに割り込み禁止のまま HALT しているとき                         |

各 `[HANG]` 行の前には、直前の 64 命令を `[CPU]  trace` 行として書き出します。同じ場所のハングは 1 回だけ報告します。`[HANG]` 行が出てもエミュレーションは止まりません。割り込み禁止の HALT で止めたいときは、REPL の `bh` を使います。

### ヘッドレスで N フレームだけ実行する

```bash
python . path/to/game.rom --machine cbios_msx2_jp --count-frame 300 --vdp-trace
```

`--count-frame N` は、SDL ウィンドウを開かずにちょうど N フレームを実行して終了します。`--vdp-trace` や `--mapper-trace` と組み合わせると、毎回同じ結果になる記録を、スクリプトから取れます。

## 既知の制限

**遅延レンダラ。** CPU は 1 フレーム分を実行し、VDP コマンドは VRAM にすぐ書き込みます。レンダラはその後、垂直帰線期間（VBlank）の始まりで 1 フレームに 1 回だけ動きます。V9938 では、フレームの途中でレジスタやパレットが変わると、変更が効いたラインからバンド単位で描き分けます。TMS9918A では、最後のレジスタの値をフレーム全体に使います。一方、VRAM への書き込みについては、どのラインで書いたかを記録していません。そのため、エミュレータは、1 フレームの中でラスタに合わせて VRAM を書き換える処理（ビームに合わせた転送、タイトル画面のダブルバッファ）を忠実には再現しません。この制限はエミュレータの基本構造から来るもので、レンダラを直しても取り除けません。

**コマンドのタイミング。** ブロックコマンド（HMMV、HMMM、YMMM、LMMV、LMMM）では、S#2 の CE ビットが立っている時間がラスタ行の種類で変わります。行の種類は、ブランクの行、スプライトなしの表示行、スプライトありの表示行の 3 つです。この時間は、実機の SONY HB-F1XD で SCREEN 5 を計測した結果に合わせてあります。計測したどのケースでも、実機との差は 2 jiffy 以内です。LINE、SRCH、PSET、POINT はすぐに終わります。VDP が VRAM にアクセスできるタイミング（アクセススロット）をサイクル単位で再現するモデルはありません。そのため、ほかの画面モードやほかのマシンでは実機と違うことがあります。

**`so` と `bs` は SP に基づくヒューリスティックです。** `so` は、SP が `so` を入力した時点の値を初めて上回ったときに止まります。スタックを切り替えるルーチン、プッシュした数より多くポップするルーチン、戻る前にもう一度呼ばれるルーチンでは、`so` が止まるのが早すぎたり遅すぎたりすることがあります。正確に止めたいときは `g ADDR` を使います。`bs` は SP を固定のアドレスの範囲と比べます。スロットの切り替えでページに RAM が正しく割り当て直されても、`bs` はそれを考慮しません。
